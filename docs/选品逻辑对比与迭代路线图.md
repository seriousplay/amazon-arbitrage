> 基于 PDF 选品逻辑文档 vs 当前 Scout 系统实现能力的全面分析

## 一、11 维选品逻辑对照

### 1️⃣ 产品成本构成

| 子项 | 要求 | 当前实现 | 差距 |
|------|------|----------|------|
| 采购成本 | 1688 采购价 | ✅ `alibaba_matcher` 搜索匹配 | — |
| 头程物流 | 国内→亚马逊仓库运费 | ❌ 仅用 `cost_multiplier=1.25` 笼统覆盖 | **用户自估 + ±15%** |
| 营销成本 | 站内广告 / 促销 / 站外推广 | ❌ 未纳入 | **用户自估 + ±15%** |
| 售后成本 | 退货率 | ❌ 部分通过 `risk_assessor` 关键词判断 | **用户自估 + ±15%** |
| 亚马逊扣费 | 佣金 + 尾程物流 + 仓储费 | ❌ 未按品类/尺寸分段计算 | **用户自估 + ±15%** |

**策略调整**：不构建 FBA 费率引擎，改为：
- 保持 `cost_multiplier` 简单系数，但在 UI 中高亮展示且支持按品类设置
- 用户可一键设置"整体成本上浮 X%"（默认 25%，范围 10%-40%）
- 利润估算显示**区间**而非单点值（如 "预估利润率 32% ± 15% = 27%~37%"）
- 爆款评分中的利润维度也使用区间评分（取低值做保守评估）

## 三、迭代路线图（三阶段）

### 🚩 Phase 1：核心选品维度补全 + 利润容忍机制（2-3 周）

**目标**：先补全独立维度（集中度、新品率、价格区间），再把"成本精度"的问题从系统责任变为用户责任。

#### 1.1 利润估算加入 ±15% 容忍区间

- [ ] **利润率区间显示机制**
  - 计算逻辑不变，但所有利润展示改为区间：`[估算值 × 0.85, 估算值 × 1.15]`
  - 界面展示：`预估利润率 32%（区间 27% ~ 37%）`
  - 用户可在 5%-25% 之间调整个人的浮动容忍度

- [ ] **成本系数用户可调**
  - `cost_multiplier` 从默认 1.25 改为按品类可配置
  - API 暴露调整端点，前端可拖拽滑块
  - 预设"保守/中性/激进"三档成本策略

- [ ] **评分算法更新**
  - `BreakoutScorer` 利润维度改用区间下限值评分（保守评估）
  - 新增用户可配的"目标利润率"参数，低于此值直接降级

#### 1.2 市场集中度分析

- [ ] **类目 Top 100 全量爬取**
  - 当前仅爬取 20-50 名，扩展至 100
  - 聚合分析：价格区间分布、品牌集中度（CR3/CR5/CR10）、卖家集中度

- [ ] **品牌独占率**
  - Top 100 中同一品牌出现频次 → 判断类目是否被大品牌垄断
  - 输出：品牌集中度指数（低/中/高）

- [ ] **价格区间分析**
  - 绘制 Top 100 价格分布直方图
  - 识别"真空区间"（无产品或销量低的价格带）
  - 输出：建议定价区间和差异化策略

#### 1.3 新品渗透分析

- [ ] **上架时间采集**
  - Amazon 详情页提取首次上架日期
  - `AmazonProduct` 模型新增 `listing_date` 字段

- [ ] **新品率与新品表现**
  - 统计类目中上架 ≤12 个月的产品数量占比
  - 新品 vs 老品的评分数量、价格、BSR 对比
  - 按上架时间分组统计销量分布

---

### 🚩 Phase 2：智能化升级（2-3 周）

#### 2.1 实时趋势引擎

- [ ] **Google Trends 集成**
  - 每日定时任务拉取品类关键词趋势
  - 替换静态内建数据为每周更新的实时趋势
  - 新增关键词热度变化趋势

- [ ] **搜索量估算**
  - 基于 BSR 排名 + 评论增长速率估算月搜索量

#### 2.2 差评分析

- [ ] **差评爬取**
  - 爬取 Top 10 产品的 1-3 星评论（采样 20-50 条/产品）
  - 中文翻译 + 关键词聚类

- [ ] **AI 差评摘要**
  - 利用 LLM 对差评做结构化摘要
  - 输出核心缺陷标签与改进方向

#### 2.3 1688 供应商纵深

- [ ] **供应商画像**
  - 采集供应商的累计成交数、回头率、评分
  - `SupplierProfile` 模型

- [ ] **相似货源推荐**
  - 对匹配到的 1688 商品，自动搜索同款不同供应商

---

### 🚩 Phase 3：产品化（2-4 周）

#### 3.1 前端管理面板

- [ ] **Vue 3 + Element Plus 前端**
  - 扫描任务仪表盘（WebSocket 实时进度推送）
  - 商品列表 + 并排对比（Amazon vs 1688）
  - 爆款评分可视化（雷达图/分级卡片）
  - 规则配置面板（拖拽调节阈值 + 成本系数滑块）

- [ ] **报告导出**
  - Excel 导出（每个产品一行，含所有评分维度）
  - 选品简报 PDF（A4 格式）

#### 3.2 生产加固

- [ ] **JWT 认证** — API 端点保护
- [ ] **性能优化** — Redis 缓存 / Playwright 浏览器池
- [ ] **监控告警** — Prometheus + Sentry

#### 3.3 智能选品助手

- [ ] **综合爆款指数**（11 维度统一为 0-1000 分）
- [ ] **一键最佳匹配**："基于当前规则，今天最佳选品是 XXX"
- [ ] **定期简报**：定时任务推送选品周报

## 六、关键决策点

1. **成本策略**：不建 FBA 费率引擎 → 用户自估 + `cost_multiplier` 品类级配置 + ±15% 利润浮动区间 ✅ 已确定
2. **差评分析**：初期用 LLM API 快速验证，后续可考虑本地模型降成本
3. **前端框架**：Vue 3 + Element Plus（与 FastAPI 生态兼容好）
4. **部署方式**：Docker Compose 足够，当前阶段单机即可
